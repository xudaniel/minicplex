# 游戏厅：傅里叶和哈希

两个游戏厅，和互动课的上下半场一一对应：

- **傅里叶游戏厅**（`index.html`）：四个游戏，十二颗星。练的是把一条弯弯曲曲的线，看成几个简单正弦波叠在一起。
- **哈希游戏厅**（`hash.html`）：两个游戏，六颗星。亲手试一试让指纹长成指定的样子有多难，让两个指纹撞在一起又有多容易。

每个游戏厅都是一个 HTML 文件，用浏览器直接打开就能玩，手机和电脑都可以。右上角可以切换中文和英文。所有计算都在浏览器里现场运行：变换用的是和 `fourier.c` 一样的两层循环，指纹用的是和 `hash_demo.c` 一样的 SHA-256。

## 文件

| 文件 | 内容 |
|---|---|
| `index.html` | 傅里叶游戏厅，单个文件 |
| `test.js` | 检查傅里叶游戏厅里的算法和出题逻辑 |
| `hash.html` | 哈希游戏厅，单个文件 |
| `hash_test.js` | 检查哈希游戏厅里的 SHA-256、挖矿和撞车 |

```bash
# 玩：用浏览器打开 index.html 或 hash.html
# 检查算法：
node test.js index.html
node hash_test.js hash.html
```

## 傅里叶游戏厅：四个游戏

### G1 调音（Tune It）

虚线是目标波形。拖动三个振荡器的频率和振幅，让你的波和目标完全重合。

- 频率 1 到 12，振幅 0 到 1（每格 0.05）。
- 重合度到 99.5% 算对上，实际上就是每个滑块都要拖到位。
- 五个关卡：热身（一个波）、两个波、三个波、像方波、随机。
- 「像方波」那一关的答案是奇数频率 1、3、5，振幅约为 1、1/3、1/5。这正是方波的开头几项。
- 可以听目标和自己的波：频率 f 对应 110 × f 赫兹。
- 卡住时可以打开目标的频谱当提示。

星星：对上「两个波」、「三个波」、「像方波」各一颗。

### G2 认谱（Spectrum Snap）

给一个波形和四张频谱，选出属于它的那一张。一局八轮：前三轮一个波，中间三轮两个波，最后两轮三个波。

错误选项是按常见的误解设计的，比如“两个频率会加在一起变成一根柱子”、“柱子高度对调”、“频率差一格”。

计分：

- 答对得 100 分。
- 速度加分最多 100 分，10 秒内线性减到 0。
- 连对加分：之前已经连对几题，就加几个 20 分。
- 答错得 0 分，连对清零。
- 八题全对并且瞬间作答，满分是 2160。

星星只看答对的题数：一局答对 5 题、7 题、8 题各一颗。

### G3 寻频（Frequency Hunt）

信号里藏着几个波。频率 1 到 16 排成一排格子，每点一格，就用那个频率去探一次，得到信号里这个频率的振幅。探针数量有限，要在用完之前把藏着的波全找出来。

| 关卡 | 藏着的波 | 探针 |
|---|---|---|
| 第 1 关 | 两个 | 6 根 |
| 第 2 关 | 三个 | 6 根 |
| 第 3 关 | 三个，起点各不相同 | 5 根 |

要点：

- 探错的结果正好是 0。哪怕只差一格，信号和探针的乘积也会完全抵消。
- 第 3 关的波挪过起点，所以会同时显示 sin 探针和 cos 探针的结果，两者合起来才是振幅。
- 每次探完，下面会画出“信号 × 探针”的曲线，可以看到面积是累加还是抵消。
- 每探中一个频率，会播放那个频率的声音。

星星：三关各一颗。

### G4 画圆（Circle Artist）

在画板上一笔画一个封闭的图形。程序把它拆成一串转动的圆，再用这些圆把图形重新画出来。拖滑块可以改变用几个圆，圆越少，画得越粗糙。

做法：

1. 把你画的线按长度均匀取 256 个点。
2. 把每个点看成一个复数，做一次傅里叶变换。每个系数就是一个圆：大小是半径，频率是转速，正负是方向。
3. 按半径从大到小排序，只用前 M 个圆来画。
4. 还原度由被丢掉的那些圆的能量算出来。

星星：

- 画一个只用 1 个圆就能还原 90% 的图形（画一个圆）。
- 画一个正好需要 2 个圆才到 90% 的图形（画一个椭圆）。
- 画一个需要 8 个以上的圆才到 95% 的图形。

校准时的一个意外发现：五角星只要 3 个圆就能还原到 95%，8 字形却要 8 个。所以第三颗星靠的是绕圈和交叉，不是尖角。示范用的心形到 90% 要 5 个圆，到 95% 要 8 个。

## 哈希游戏厅：两个游戏

### H1 挖矿（Dig）

在一句话后面加一个编号，再算它的 SHA-256。指纹开头的 0 越多越稀有。不停地换编号，直到挖出一个开头有足够多位 0 的指纹。

- 目标有四档：开头 8、12、16、20 位是 0。
- 每试一次，挖中的机会是 2 的“位数”次方分之一。所以 16 位平均要试 65,536 次，20 位平均要试 1,048,576 次。每多要一位，工作量翻一倍。
- 可以用手一下一下挖，也可以让机器挖。机器每一帧挖一批，批量会自动调整，页面不会卡住。
- 挖中之后，页面给出那句话和验证命令。找到它很费力，验证它只要算一次，这就是“工作量证明”。

例子：用默认的句子挖 16 位，挖中的是 `minicplex #197862`，试了 197,863 次，是平均值的 3 倍。用上一级目录的 C 程序验证：

```
$ ./hash_demo "minicplex #197862"
原句：minicplex #197862
SHA-256：00004cb33c61c8f4d66ec8ac3b4055957900fd68dac8637e535b22187855767f
```

星星：用手挖出开头 4 位是 0 的指纹；让机器挖出 16 位；让机器挖出 20 位。

### H2 撞车赌局（Crash Bet）

把一句句话扔进格子里。每句话的指纹对格子数取余，决定它落进哪一格。先下注：平均扔多少句，才会第一次有两句落进同一格？然后页面跑 200 场，把平均值和你的下注放在一起比。

| 桌 | 格子数（每次随机选一个） |
|---|---|
| 第 1 桌 | 64、100、144 |
| 第 2 桌 | 400、900、1600 |
| 第 3 桌 | 10,000、40,000、65,536 |

- 前两桌会把其中一场演示出来：格子一格一格被占，直到撞车。第 3 桌格子太多，直接跑 200 场。
- 结果是一张直方图：200 场各扔了多少句，平均值在哪，你的下注在哪。
- 这是生日问题。经验公式是大约 1.25 × √格子数，所以格子多 4 倍，撞车只晚 2 倍。365 个格子时平均是 24.6 句。
- 每次换桌，格子数都会变，所以要靠公式，背不了答案。

星星：三桌各有一次下注落在 200 场平均值的 20% 以内。

## 成绩和设置

- **成绩榜**在每个页面的最下面。
  - 傅里叶：调音每关最快用时、认谱最高一局得分、寻频每关剩余探针数、画圆最圆和最复杂的一次。
  - 哈希：挖到过最多的 0 和机器最快速度、每一桌最准的一次下注。
- 拿满星星后（傅里叶十二颗，哈希六颗），成绩榜会变成通关卡片。
- 调音的计时从第一次拖动滑块开始。认谱每一轮的计时从四个选项出现在屏幕上开始。
- 右上角的 ♪ 可以关掉游戏音效。「听目标」和「听我的」两个按钮在静音时仍然能用。
- 星星、成绩、语言和声音设置只存在当前浏览器里，换一台设备不会带过去。两个游戏厅各存各的。

## 怎么核对的

`node test.js index.html` 检查这些：

- 调音：四个固定关卡按答案设置后重合度是 100%，差一格就低于 99.5%；300 个随机目标都能用滑块精确对上。
- 认谱：生成 3200 轮，每轮四个选项互不相同，正确选项的柱子和真正做变换算出来的一致。
- 寻频：900 个随机棋盘，藏着的频率探出来正好是它的振幅，其余频率正好是 0。
- 画圆：圆、椭圆、8 字形分别触发对应的那颗星；还原度随圆的数量只增不减，用完所有圆时是 100%。

另外用无头浏览器自动玩过一遍：调音对上两关，认谱打完一局，寻频赢一关、输一关，画板上用模拟的笔画画了三个图形，切换了声音和语言，全程没有报错。

`node hash_test.js hash.html` 检查这些：

- SHA-256：2010 个输入和 Node 自带的实现逐一对比，包括补位的几个边界长度。
- 挖矿：8、12、16、20 位各挖一次，挖出的编号用 Node 独立验证确实有那么多位 0；前三档还确认了它是第一个满足条件的编号。
- 撞车：九种格子数各跑 200 场，平均值和理论值相差都在 12% 以内。

哈希游戏厅同样用无头浏览器自动玩过一遍：手挖 23 下，机器挖 16 位和 20 位，三桌赌局有赢有输，六颗星都能拿到，全程没有报错。

没有核对过的：声音实际听起来怎么样，以及挖矿进行中和撞车演示的动画看起来怎么样。
