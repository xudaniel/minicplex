# 搅乱，与分开：手写 Hash 和傅里叶变换

用纯 C 从零写出 SHA-256 和傅里叶变换，再配一门八个实验的互动小课。

- **Hash 负责搅乱**：把任意长的内容压成固定长度的指纹，改一位变一半，回不去。
- **傅里叶负责分开**：把混在一起的波按频率一根一根分出来，还能原样拼回去。

这个目录和求解器本身没有依赖关系，放在 minicplex 里是因为目的相同：把一个算法从零写出来，写到能看懂、能核对为止。

**在线版：<https://xudaniel.github.io/minicplex/hash-fourier/>**（首页连着互动课和两个游戏厅，手机也能用）

所有 C 文件只 `#include <stdio.h>`。数据类型、字符串函数、`sin`、`cos`、开方都是手写的，没有用任何加密库或数学库。

## 一、Hash

### 最简单的版本：FNV-1a

```c
unsigned int hash(const char *s) {
    unsigned int h = 2166136261u;   // 起点：一个固定的数
    while (*s) {
        h ^= (unsigned char)*s++;   // 1. 把一个字节混进去
        h *= 16777619u;             // 2. 乘一个质数，把它搅散
    }
    return h;
}
```

```
我的一句话    → 21838ace
我的一句话。  → 5656f755
```

它只有 32 位，大约 7.7 万个字符串就有一半概率撞上重复。适合做哈希表，不能用来保护密码或校验文件。

### SHA-256

`hash_demo.c` 分四步：

1. **补位**：末尾加 `0x80`，补 0，最后 8 字节写入原文的位数，凑成 64 字节的整数倍。
2. **起点**：8 个初始值，取自前 8 个质数平方根的小数部分。
3. **压缩**：每块先展开成 64 个 32 位数，再把 8 个状态 `a` 到 `h` 搅 64 轮。每轮用到选择（`CH`）、投票（`MAJ`）和循环移位（`EP0`、`EP1`）。64 轮后把结果加回原状态，所以没法倒推。
4. **输出**：8 个数拼成 32 字节，打印成 64 个十六进制字符。

```
$ ./hash_demo "hash为什么基本就是唯一的"
原句：hash为什么基本就是唯一的
SHA-256：2878a4e9a062efa46dbea845b7a04df4d36baa049c2b96ed54607027f08cad48

句尾加一个“。”：hash为什么基本就是唯一的。
SHA-256：43e5cfab28efe410deafa5c4cc277c38eea762b52445c563353ca79a71cc3179

256 位里有 121 位不同（随机的话约 128 位）
```

### 逐轮追踪

`--trace` 把两句话每一轮的 `a` 到 `h` 记下来对比。上面那个例子里：

| 轮 | 不同的位数（满 256） |
|---|---|
| 0 到 7 | 0 |
| 8 | 14 |
| 9 | 47 |
| 10 | 80 |
| 11 | 109 |
| 12 | 127 |
| 13 到 63 | 在 113 到 144 之间 |

句号改动的是第 32 到 36 字节，落在消息字 `m[8]`、`m[9]`，长度字段 `m[15]` 也跟着变。前 8 轮用的数据两边一样，所以差别从第 8 轮才进来，4 轮之后就乱到了一半。

### 为什么“基本唯一”

严格说不唯一：输入无限多，输出只有 2²⁵⁶ 种，一定存在重复。但要有一半把握撞出一次，大约要试 2¹²⁸ 次，实际上做不到。

## 二、傅里叶变换

### 直白的写法：DFT

```c
for (int k = 0; k < N; k++) {           // 对每一个频率 k
    for (int n = 0; n < N; n++) {       // 把所有采样点过一遍
        re[k] += x[n] * my_cos(a);      // 和 cos 波的相似度
        im[k] -= x[n] * my_sin(a);      // 和 sin 波的相似度
    }
}
```

拿一个每 N 个点转 k 圈的标准波，和信号逐点相乘再求和。信号里有这个频率，乘积就累加成一个大数；没有，就正负抵消成 0。

```
$ ./fourier
信号 = 频率 3（振幅 1.0）+ 频率 7（振幅 0.5），32 个采样点

频率  振幅
  3   1.000  ██████████████████████████████
  7   0.500  ███████████████
其余   0.000
```

### 快的写法：FFT

1. 把 N 个点按位置分成偶数位和奇数位两组。
2. 两组各自做一次 FFT（递归）。
3. 合并：`X[k] = 偶[k] + w·奇[k]`，`X[k + N/2] = 偶[k] − w·奇[k]`。同一个 `w·奇[k]` 用两次。

每层做 N/2 次，一共 log₂N 层。点数必须是 2 的幂。

```
$ ./fft
4096 个点，信号 = 频率 50（振幅 1.0）+ 频率 120（振幅 0.5）

FFT 找到的峰：频率 50 振幅 1.000   频率 120 振幅 0.500

运算次数：
  DFT：  16777216 次  （N × N）
  FFT：     24576 次  （N/2 × log2 N）
  FFT 少算 682 倍

两种算法结果的最大差距：2.46e-11
```

## 三、互动课程

`course/index.html` 是一个单文件网页，手机上也能用。八个实验，每个先猜一题，再动手：

| # | 实验 | 做什么 |
|---|---|---|
| 01 | 指纹 | 写一句话，256 个格子实时显示它的 SHA-256 |
| 02 | 雪崩 | 改一个字，看有多少位变了 |
| 03 | 六十四轮 | 拖滑块逐轮看 `a` 到 `h`，`--trace` 的可视化版 |
| 04 | 撞车 | 把指纹截短到 8 至 24 位，现场找两句指纹相同的话 |
| 05 | 混音 | 调三个波的频率和振幅，波形和频谱一起动 |
| 06 | 探针 | 拿标准波去乘信号，看乘积是累加还是抵消 |
| 07 | 对半拆 | 点数从 8 拖到一百万，对比 DFT 和 FFT 的次数 |
| 08 | 回得去吗 | 用傅里叶去杂音，再试着从指纹倒推原句 |

页面里的算法是照着上面几个 C 文件用 JavaScript 重写的，在浏览器里现场运行。

在线版：<https://xudaniel.github.io/minicplex/hash-fourier/course/>

## 怎么核对的

- `hash_demo.c`：7 种长度的输入（0、1、55、56、64、120 字节和一句中文）和系统的 `sha256sum` 逐一对比，全部一致。55 和 56 字节是补位要不要多加一块的边界。
- `simple_hash.c` 和 `simple_hash.py`：两边结果一致。
- `fourier.c`、`fft.c`：峰的位置和振幅用 Python 独立算过，一致。
- 课程页面：例句的 hash、121 位不同、第 8 到 12 轮的位数，都和 C 版一致。
- 游戏厅：`arcade/test.js` 和 `arcade/hash_test.js` 检查六个游戏的算法和出题逻辑，两个页面都用无头浏览器自动玩过一遍，详见 `arcade/README.md`。

## 说明

这些代码是为了看懂原理写的。真要用 SHA-256，请用 OpenSSL 或语言自带的库（比如 Python 的 `hashlib`）：它们更快，也经过了严格的审查。
